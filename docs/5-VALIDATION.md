## 非目标

下列能力继续排除在阶段 5 之外。它们出现在压缩、检索或人格上下文里，也不算交付：

- Dream Cycle；
- 图记忆；
- 复杂衰减；
- 自动 Skill 晋升。

两条边界必须保持：

- 压缩摘要是 L0 工作上下文，不是长期记忆。只有独立的记忆写入从中抽出可用事实，
  才可能成为可检索记录。
- 人格推断不是用户事实。人格控制说话语气和行为；检索到的记忆提供用户或项目事实。
  用户偏好不得静默改写人格定义。

具体 Token 预算、压缩阈值和 embedding 实现仍是 DESIGN 第 15 节的未决项。
P5.5 只要求普通轮次停在基础包，超预算必须截断，不在本文件规定具体数字。

## 组装顺序

每一轮提示按这个顺序组装，不得调换：

```text
Host policy
→ compact persona
→ L1
→ L0
→ progressive L2–L5
```

与 DESIGN 第 9.2 节的对应关系：

```text
Host-enforced policy
→ compact personality profile
→ L1 standing rules
→ L0 current task context
→ progressively loaded L2–L5 memory pack
```

Host policy 在最前，因为策略由 Host 执行，不能被人格或记忆改写。紧凑人格只决定
表达和行为，不提供用户事实。L1 常驻加载；L0 只带当前任务。L2–L5 按需渐进加载，
普通轮次停在基础包。

## 四个有序 PR

按顺序合并：前一个合并之后，才开始下一个。不主动合并。

| 顺序 | PR                              | 覆盖             |
| ---- | ------------------------------- | ---------------- |
| 1    | Schema + ownership              | P5.1、P5.2       |
| 2    | Write + retrieval + progressive | P5.3、P5.4、P5.5 |
| 3    | Compression + persona           | P5.6、P5.7       |
| 4    | Client + eval                   | P5.8、P5.9       |

顺序要守住，是因为后一步的通过条件依赖前一步的契约：没有归属门禁就开放写入，
Agent 可能改写用户行；检索和渐进加载使用已区分的层次与来源；压缩摘要必须停在
L0；客户端和评估对着已经落地的记录，而不是尚未存在的记忆层。

每个 PR 的门禁是 `pnpm check` 通过。门禁通过只说明该切片可以审阅，不表示阶段 5
完成，也不授权跳过尚未合并的后续 PR。

## 完成定义

阶段 5 完成需要同时具备：

1. 自动门禁证据：四个 PR 各自 `pnpm check` 通过，且合并顺序符合上一节。
